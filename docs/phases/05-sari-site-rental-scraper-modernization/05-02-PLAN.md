# Plan 05-02: Snapshot-Aware Storage & Observability

<objective>
Make the daily sarı site data durable and auditable: CSVs stay the engine
output; Mongo becomes the queryable history with per-run observability.
</objective>

<tasks>

### Task 05-02-01: Design Mongo schema (research report B10)

- `listings_current`: `{ilanId, city, district, rooms, price, snapshot_date}` —
  one doc per ilanId per day (snapshot semantics).
- `listing_observations`: append-only price/availability history per ilanId
  (enables the inflation study's time series without detail pages).
- `crawl_runs`: `{city, date, started_at, finished_at, brackets, pages, rows,
  manual_solves, status, error}` — one doc per daily run per city.

Apply mongodb-schema-design skill: index plan (`ilanId+snapshot_date`,
`city+snapshot_date`), TTL for raw snapshots beyond study window, document
limits review (no unbounded arrays — observations as separate collection).

### Task 05-02-02: CSV→Mongo sync adapter

- Read `InflationItems/Datas/HousesRent/<City>/<date>.csv`; bulk-upsert into
  `listings_current`; append diffs to `listing_observations`; write the
  `crawl_runs` record (success or failure with error).
- Idempotent: re-running a day replaces that day's snapshot, never duplicates.
- Engine stays CSV-only; the adapter runs after (same scheduler step).

### Task 05-02-03: Reconciliation checks

- Compare per-city row counts: engine CSV vs Mongo vs recon estimates.
- Flag deltas >15% or zero-row days; report via crawl_runs.status = drift.

### Task 05-02-04: Domain/API integration (optional)

- If the dashboard (phases 1–3) is asked to show rental series, add a Mongo
  adapter behind the existing use-case interfaces only; no contract changes
  to Falcon endpoints without a new plan.

### Task 05-02-05: Observability + docs

- `scripts/verify_rental_data.py` (or pytest): schema, count, drift checks.
- Update docs/APPROACH.md (storage section), STATE.md, ROADMAP.md.

</tasks>

<success_criteria>

1. Mongo collections exist with the B10 schema; daily sync is idempotent.
2. Reconciliation passes on at least two consecutive daily runs.
3. crawl_runs gives a one-command status view of the last N days.
4. No dashboard contract changed without its own plan.
</success_criteria>

<risks>

- Mongo not available locally → keep CSVs canonical; adapter optional until
  infra exists (config flag).
- Snapshot growth → TTL policy from research report; archives after study end.
- Drift detection noise → allowlist price-level drift; only row-count drift
  flags runs.
</risks>

<dependencies>

- Plan 05-01 (live runs produce real data to sync).
- MongoDB access (local or existing infra).
</dependencies>
